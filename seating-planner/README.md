# 婚礼桌位编排器（离线）

纯前端、无服务端的桌位编排工具：React + TypeScript 管理宾客，Konva 绘制场地，
glpk.js（GLPK WASM，内部 Web Worker）求解混合整数规划，工程持久化到 IndexedDB。

## 运行

```bash
npm install
npm run dev      # 开发
npm run build    # 构建（tsc + vite）
npm test         # 求解器与几何的端到端验证（Node）
```

## 功能与需求映射

| 需求 | 实现 |
| --- | --- |
| 宾客侧栏 | `src/components/GuestSidebar.tsx`：增删改、RSVP、儿童、家庭组、忌口 |
| 场地绘制 | `src/components/FloorCanvas.tsx`（react-konva）：圆/矩形桌、椅子、拖动布局 |
| 自动排座 | `src/solver/model.ts` 建模 + `src/solver/solve.ts` 调 glpk.js（浏览器版自带 Worker + WASM） |
| 硬约束 | 家庭同桌（z[f,t] 变量）、明确避让（同桌和 ≤ 1）、容量（席位 ≤ 1）、儿童仅限允许儿童的桌 |
| 软约束 | 靠近主桌偏好 → 目标函数距离代价，求解后显示总代价与逐宾客明细 |
| 锁定席位 | 锁定项固定为 1，自动排座不得移动（建模时该席位不再生成其他变量） |
| 禁占区 | `src/geometry.ts`：过道/消防出口多边形与桌、椅做相交检查，仅几何提示，**不构成安全认证** |
| 同名宾客 | 稳定编号 `G-0001…` + 同名序号 `王芳 (#2)`，编号永不复用 |
| 忌口独立存储 | `project.dietary` 以 guestId 为键，与席位无关；导出桌卡（`src/export.ts`）换座不丢忌口 |
| 未回复宾客 | `rsvp=pending/declined` 不进入模型，侧栏单独标识 |
| 儿童椅占位 | 儿童占一个普通席位并标记 `isChildSeat`，画布绿色显示 |
| 无解样例 | 样例工程自带「家庭同行 ∧ 明确避让」冲突，建模阶段即报告冲突条目 |
| 撤销 | 所有手工操作入撤销栈（`store.tsx`，上限 50 步），含“应用自动方案” |
| 手工 vs 自动 | 自动方案快照 + 当前方案偏好代价估算，显示差异席位数与代价差 |
| 持久化 | IndexedDB（`src/db.ts`），编辑防抖自动保存，刷新恢复 |
| 撤桌重排 | 字典序两阶段：阶段一最小化换桌人数，阶段二在该上界下最小化偏好代价（`solver/solve.ts`） |
| 容量核算 | 临时到场（walkin）计入实际需求；未回复计入候选；报告显示候选全部到场是否超员 |
| 交换链 | `src/swapchain.ts`：链内宾客先离席再按序落座，逐步验证 + 终态复核，失败则整条不落地 |
| 菜品差异 | `src/catering.ts`：撤单/忌口增减 diff；已出菜（servedAt）为不可回滚事实 |
| 过期拦截 | 每次变更递增数据版本，求解结果返回时版本不一致即作废（`src/projectOps.ts`） |
| 打印守卫 | 桌卡只来自最新确认布局（布局 vN），求解中或有未消费结果时禁止打印 |

## 样例验证路径

1. 打开应用即载入样例：直接点「运行重排」→ 报无解并列出冲突（王强/李梅 家庭同行与避让矛盾）。
2. 在右侧面板删除该避让 → 再次求解 → 得到最优解与偏好总代价，点「应用该方案」。
3. 孙奶奶、张伟已锁定，任何自动求解都不会移动；王小宝/张乐乐（儿童）只会排到 T1/T2。
4. 陈静/刘洋/赵敏 未回复，不参与排座（计入候选容量）；郑浩已婉拒。
5. 拖动 T1 到主通道上 → 画布红框 + 违规列表提示（几何检查）。
6. 「打印桌卡」生成可打印 HTML，忌口随宾客而非席位，页眉含布局版本号。

## 撤桌重排（开席前场景）

1. 样例中约一半宾客已入席。点「演示：撤掉 T3/T4」→ 4 位宾客被释放，菜品/忌口差异立即生成：
   未出菜的「清蒸石斑」「时令时蔬」撤单；已出菜的「佛跳墙」作为事实保留，**不可回滚**。
2. （可选）点「锁定全部已入席」把确认不动的宾客全部锁定。
3. 点「运行重排」→ 字典序求解：**先最少换桌，再最小化偏好代价**。结果显示换桌人数与偏好代价；
   已入席宾客非必要不动（同桌换位也有 epsilon 代价），锁定宾客绝不被挪。
4. 容量核算行：剩余席位 / 实际需求（含临时到场）/ 候选（未回复）/ 候选全部到场是否超员。
5. 「+ 临时到场」在求解进行中点击 → 数据版本变化，**过期结果被拦截**，不会写入状态也不会进入打印。
6. 「演示：9人家庭到场」→ 家庭必须同桌但剩余最大桌容量 8 → 求解报无解并指出冲突。
7. 「演示：两人循环换座」在交换链面板生成 A→B、B→A 链节，「验证并执行」原子落地；
   任何一步无合法落点（锁定席位、儿童桌限制、终态避让/家庭冲突）→ 整条链不落地。
8. 「打印桌卡」只读取最新确认布局（布局 vN）；求解进行中或存在未处理的新结果时被拦截。

## 说明

- 禁占区检查为纯几何重叠检测，不声称通过任何消防/安全认证。
- 求解时间上限 30 秒（`tmlim`），超时返回当前可行解。
- 求解带 600ms 演示延迟，让“求解中新增到场 → 过期拦截”可复现。
